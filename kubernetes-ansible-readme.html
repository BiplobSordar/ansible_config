Production-grade Ansible automation
for a highly available Kubernetes cluster on AWS.

This project takes raw EC2 infrastructure and turns it into a fully operational, monitored, GitOps-ready Kubernetes platform — provisioning, joining, networking, and validating a 3-node control plane and dynamically scaled worker fleet, end to end.

Ansible Terraform AWS EC2 Kubernetes / kubeadm Calico CNI Helm Argo CD Prometheus / Grafana / Loki
01 / OWNERSHIP
SEPARATION OF CONCERNS

Two systems, one clean boundary

Infrastructure and configuration are deliberately decoupled — a pattern that keeps environments reproducible and prevents drift.

▲ Terraform — infrastructure

  • VPC & subnets
  • Security groups
  • EC2 instances
  • Load balancers & NAT gateways
  • IAM & RDS

⎈ Ansible — configuration (this repo)

  • OS & runtime prep (containerd)
  • kubeadm init / join
  • Calico networking + Helm
  • Platform & monitoring stack
  • Automated cluster validation

07 / PRINCIPLES
ENGINEERING DECISIONS

Why it's built this way

→
Infra / config split
Terraform never touches OS or cluster state; Ansible never provisions AWS resources.
→
Dynamic inventory
No hard-coded IPs — nodes are discovered from AWS tags, resilient to ASG churn.
→
Idempotent by design
Re-running site.yml never disrupts an already-healthy cluster.
→
Validation-first
Nothing is declared "ready" without an automated, layer-by-layer health check.
